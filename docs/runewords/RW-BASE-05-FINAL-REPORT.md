## 남은 제한 및 판정

- `EPERM`의 원인을 재확인했습니다. 동일한 Windows 작업 폴더에서 기본 제한 실행으로는 `.next` 생성 중 경로별 `EPERM`이 났지만, Codex의 격리된 파일시스템 쓰기 제한을 제거한 승인된 실행에서는 `Next.js 16.4.6` Webpack 빌드가 프리렌더까지 통과했습니다. 이를 근거로 프로젝트 코드/경로 충돌이 아니라 Codex 제한 실행 샌드박스가 빌드 산출물 쓰기를 차단한 것으로 판정합니다. 향후 Codex에서 Windows 프로덕션 빌드할 때는 `.next` 전체를 반복 삭제하는 대신 로컬 빌드에 제한 없는 승인 실행을 사용합니다. Vercel 서버 빌드는 해당 로컬 샌드박스를 거치지 않습니다.
- 빌드 과정에서 `next@16.4.3`이 보안 업데이트가 필요한 버전으로 차단되었습니다. `next` 및 `eslint-config-next`를 `16.4.6`으로 맞추고 `package-lock.json`을 갱신했으며, 패치 버전 빌드가 통과했습니다. Nov 3 공식 보안 업데이트에서 16.4.x 패치가 제공됐고, 현재 16.4.6 릴리스가 이를 포함하는 상위 패치입니다.
- 현재 추천 베이스 후보는 전체 게임 베이스 목록이 아닌 62개 subset입니다. 102개 항목 커버리지는 후보 subset 안에서 추천 연결이 있다는 의미이지, 모든 가능한 베이스를 검토했다는 뜻은 아닙니다.
- 자동 검증은 장비 분류와 해당 베이스의 최대 가능 소켓 상한을 검사합니다. 아이템 레벨별 라주크 결과·큐브 확률을 확정하지 않으며 게임 클라이언트에서 직접 제작하는 수동 검증은 수행하지 않았습니다.
- 현재 기본 모드 RotW 온라인 래더 3.4와 저장 Variant의 장비/소켓 조합을 자동 검사했습니다. Classic·LoD와 개별 모드에서의 실게임 제작 가능성은 별도 검증이 필요합니다.
- 추천 목적과 이유는 베이스 후보 분류를 돕는 안내입니다. 요구 능력치·피해량·방어력·공격 속도·거래 가치까지 포함한 빌드별 최적 베이스 순위는 아닙니다.
