# IAS-3-B-2 A2 후속 검증 계획

## 공개 데이터 후보 단계

1. 지원 게임 빌드를 고정하고 D2R `AnimData.d2`의 Paladin A2 모션 레코드 식별자를 확보한다.
2. 성기사 인간형 Normal Attack A2가 무기 클래스별로 어떤 COF/AnimData 항목에 연결되는지 확인한다.
3. Crystal Sword(WSM 0), Phase Blade(WSM −30), War Hammer(WSM +20)의 실제 클래스 및 무기별 속성을 확인한다.
4. A2의 `Frames`, `AnimSpeed`, `E`, `StartingFrame`, `ActionFrame` 등 입력을 출처와 빌드 해시를 붙여 보존한다.
5. A1 계산식에서 StartingFrame만 바꾼 추정은 A2 근거로 간주하지 않는다. 공개 데이터가 빠져 있으면 A2는 계속 차단한다.

## 게임 내 실측 후보 단계

### 통제 조건

- 게임/리전/빌드 번호와 패치 일자를 기록한다.
- 고정된 성기사 캐릭터를 사용하고 속도 변화가 없는 인간형을 유지한다.
- 무기별 테스트 캐릭터를 준비한다. 무기 외 장비 IAS 0, 용병/파티 오라 없음, 자체 오라 없음, 버프/디버프 없음으로 시작한다.
- 무기 자체 IAS와 무기 외 IAS를 별도 기록한다. 무기 내장 IAS가 있는 경우 이를 장비 IAS와 혼동하지 않는다.
- 단일 대상에 동일한 일반 공격 입력을 반복하고, 적중 이벤트가 전체 모션 길이를 대체하지 않도록 관측한다.

### A1/A2 식별

실측 전 A1/A2를 판별하는 재현 가능한 기준이 필요하다. 사용자 입력만으로 공격 동작을 구분할 수 있다고 가정하지 않는다. 먼저 게임 데이터(AnimData/COF)와 프레임 영상의 팔레트/모션 식별을 연결하고, 게임이 선택한 모션을 로그나 디버그 수단으로 확인할 수 있는지 검증한다. 이 연결을 확립하지 못하면 측정 결과는 “성기사 일반 공격, 애니메이션 미식별”로만 기록하고 A2 데이터로 분류하지 않는다.

### 표본 설계

- 각 후보 브레이크포인트 `b`마다 `b−1`, `b`, `b+1` IAS를 측정한다. 현재 A1 breakpoint를 A2 정답으로 미리 가정하지 않는다.
- 각 조건에서 유효한 연속 공격 간격 100회를 목표로 하며, 최소 30회 미만이면 결론을 내리지 않는다.
- IAS 외 입력 조건을 유지하고 각 run을 최소 3회 반복한다.
- 결과는 게임 시뮬레이션 프레임 간 간격의 분포, 중앙값, 최빈값, 범위를 기록한다. 입력/타격 지연이 섞인 표본은 사전 기준에 따라 제외하고 제외 사유를 보존한다.
- 여러 IAS를 넓은 간격으로 탐색한 후 전환점 주변을 이진 탐색하고, 최종 경계 ±1을 재측정한다.

### 25Hz 프레임과 영상 처리

D2R 시뮬레이션 프레임은 25Hz 단위로 해석하되, 60/120fps 영상 프레임을 게임 프레임과 동일시하지 않는다. 녹화 영상은 고정 프레임레이트와 오디오/화면 이벤트 타임스탬프를 보존하고, 반복 모션의 시작 기준점을 같은 애니메이션 이벤트로 잡는다. 캡처 프레임 사이 보간, VFR, 렌더링 지연, 공격 입력 지연을 불확실성 항목으로 기록한다. 영상 프레임은 게임 프레임 계수의 관측 수단이지, 단독으로 A2 식별의 증명은 아니다.

## VERIFIED 승격 체크리스트

1. 성기사 인간형 A2로 모션이 명시적으로 식별됨.
2. 무기 클래스/WSM 및 게임 빌드가 기록됨.
3. 애니메이션 데이터 출처와 A2 StartingFrame이 확인됨.
4. 전체 애니메이션 길이와 타격 ActionFrame을 분리함.
5. 독립 구현 또는 게임 실측이 같은 breakpoint 전후 변화를 재현함.
6. 원시 표본, 측정 도구, 계산 코드, 제외 기준, 불확실성이 재현 가능하게 보존됨.
7. A1 코드의 단순 재사용이 아님을 검토함.

전체 애니메이션 프레임 검증과 런타임이 실제로 A1/A2 중 무엇을 선택하는지 검증은 별도의 통과 판정을 가진다.
